# 禁止项目与功能点清单

本清单用于项目选型、单条功能点设计和最终题面三层审查。任一层的**核心实体、核心工作流或主要用户目标**命中即淘汰；禁止只替换名词后继续使用同一业务。

## 特别禁止（最高优先级）

- 查账 / 账务类：支付对账、财务报表、结账、记账、账本、往来对账，以及一切以查账、对账、记账、财务核算为核心的系统。
- 订单类：电商订单、购物车、外卖点餐、采购单 / 采购订单、预订订单，以及一切以订单为核心实体的系统。

只要功能点本身命中以上两类，即使仓库总体名称看似属于其他领域，也必须淘汰。

## 游戏 / 图形

- 贪吃蛇、打砖块、俄罗斯方块、坦克大战及其变种。
- 粒子 / 物理模拟：星系、烟花、落沙、布料。
- 塔防、2D 解谜、潜行、平台跳跃、喂食小动物。
- 记忆翻牌、连连看、五子棋等棋类、2048、扫雷、打地鼠。

## 平台 / 业务系统

- 权限 RBAC 后台、仓库库存、投票问卷、考勤 OA、图书借阅、博客 CMS。
- 医院挂号 / 问诊、CRM、IM 私信、拍卖、停车场、工单客服。
- 商品 + Excel 导入、积分商城。
- 各类预约 / 预订系统，包括酒店、会议室、健身、美容、宠物就诊等。

## 本地 / 桌面工具

- 命令行 CLI、代码片段管理器、批量重命名、截图标注。
- 文件管理 / 同步、书签、密码管理器。

## 数据可视化 / 前端页面

- 报表统计、Streamlit、CSV 看板。
- 记账、健康健身、菜谱、天气、番茄钟、习惯打卡。
- 音乐播放器、旅行日记、观影记录。

## 判定方法

1. **先看项目**：项目的主要用户、核心实体和主流程是否命中禁区。
2. **再看功能点**：允许项目中的某个局部功能若落入禁区，也必须换功能点，不能继续设计缺陷。
3. **最后看题面**：`user_query`、`success_criteria` 或 `gold_root_cause` 出现禁区语义，回到功能点阶段重新选题，不能只删词或换同义词。
4. **语义优先**：脚本的关键词检查只是最低门禁。即使没有命中关键词，只要业务实质等价，人工审查仍判不合格。

示例中的“资产调拨已经送到外部、重开事务、账面和外部对不上”同时落入仓库库存 / 资产调拨与账务核对语义，应在功能点设计阶段淘汰。把“账面”改成“内部状态”并不能让同一资产调拨流程变成允许题目。
